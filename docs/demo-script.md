# 시연 대본 (12.11 학기 발표)

시연 흐름: 교수 로그인 → 과제 생성(조장 지정) → 조장이 초대 링크 발급 → 학생이 링크로 합류 → 조장이 역할 배정 → 조원이 산출물 업로드 → 조원·교수가 열람·다운로드 → 조원이 동료평가 제출.
2026.10.26 새로 clone 한 폴더에서 `docker compose up -d --build`로 켜고 이 대본 그대로 끝까지 리허설했습니다. 걸린 시간은 약 7분입니다.

## 1. 준비

### 전날

- 저장소 맨 위 폴더에서 `docker compose up -d --build`. 처음에는 몇 분 걸립니다.
- 브라우저로 http://localhost:5173 을 열어 로그인 화면이 나오는지 봅니다. `127.0.0.1:5173`으로 열면 로그인이 막힙니다(백엔드가 `localhost`만 허용).
- 올릴 파일 3개를 바탕화면에 둡니다. 한글 이름 그대로 둡니다(다운로드에서 한글 이름이 깨지지 않는 것을 보여 줍니다).
  - `ERD 초안 v1.txt`, `ERD 초안 v2.txt` (이서연이 올림)
  - `화면 설계서.txt` (박도윤이 올림)

### 시작 5분 전

- 데이터를 처음 상태로 되돌립니다. 서버가 켜질 때마다 데이터베이스를 새로 만듭니다.

  ```powershell
  docker compose restart backend
  ```

  20초쯤 뒤 http://127.0.0.1:8080/members/me 가 `{"code":"UNAUTHORIZED",...}`를 보이면 준비된 것입니다.
- 이때부터 끝날 때까지 `gradlew build`를 실행하지 않습니다. 빌드의 테스트도 데이터베이스를 처음 상태로 되돌립니다.
- 브라우저 창 하나에 **탭 4개**를 엽니다. 탭마다 주소창에 http://localhost:5173 을 직접 입력합니다.
  - 로그인 정보는 탭마다 따로 저장됩니다(sessionStorage). 그래서 탭 하나에 한 사람씩 로그인합니다.
  - 링크를 Ctrl+클릭이나 "새 탭에서 열기"로 열면 원래 탭의 로그인이 복사될 수 있습니다. 새 탭은 주소를 직접 입력해 엽니다.
- 탭 1에만 교수로 로그인해 둡니다. 나머지 탭은 로그인 화면에 둡니다.
- 화면 확대는 Ctrl + `+`로 125~150%. 뒤쪽 자리에서도 글자가 보이게 합니다.
- 화면 색은 운영체제 설정(라이트·다크)을 따릅니다. 프로젝터에서는 라이트가 잘 보입니다. 로그인한 뒤 위쪽 막대의 "라이트"/"다크" 버튼으로 바꾸면 모든 탭에 기억됩니다.
- 위쪽 막대에는 로그인한 사람의 이름과 회원 유형, 테마 버튼, 로그아웃이 있습니다. 로고 "발자국"을 누르면 과제 목록으로 갑니다.

## 2. 계정

아래는 시작 계정입니다. 로그인 화면 아래 "시작 계정으로 로그인 (개발·백업용)"을 펼쳐서 입력합니다. 비밀번호는 모두 `pass1234`입니다.
구글(학교 계정)로 시연하려면 4명의 학교 계정을 Google Cloud의 테스트 사용자에 넣고, 교수 계정을 `PROFESSOR_EMAILS`에 넣고(`backend/README.md`의 "구글 로그인"), 같은 브라우저에 4개 계정이 모두 구글 로그인돼 있어야 합니다. 이때는 시작 데이터의 과제·조가 없으므로 장면 1부터 새로 만듭니다.

| 탭 | 계정 | 이름 | 이 시연에서 하는 일 |
|---|---|---|---|
| 1 | professor@example.com | 이교수 | 과제 생성, 산출물 열람·다운로드 |
| 2 | student01@example.com | 김민준 | 1조 조장. 초대 링크 발급, 역할 배정 |
| 3 | student02@example.com | 이서연 | 링크로 합류, 산출물 업로드, 동료평가 제출 |
| 4 | student03@example.com | 박도윤 | 링크로 합류, 산출물 업로드 |

2조 조장으로는 student06@example.com(강지우)을 지정합니다. 2조는 화면에 조가 여러 개인 것을 보이려고만 씁니다.

## 3. 장면별 대본

"말할 것"은 예시입니다. 굵은 글씨는 꼭 짚을 점입니다.

### 장면 1. 교수가 과제를 만든다 (탭 1, 약 1분 30초)

| 누를 것 | 화면에 나오는 것 |
|---|---|
| "과제 목록" 제목 오른쪽의 "+ 과제 만들기" | 과제 만들기 화면. 노란 상자에 "등록한 과제는 고치거나 지울 수 없습니다." |
| 과제명 `웹프로그래밍 조별과제`, 시작일 `2026-11-16`, 종료일 `2026-12-11` | |
| 1조 조장 이메일 `student01@example.com` | |
| "조 추가" → 2조 조장 이메일 `student06@example.com` | "조와 조장 (2개 조)" |
| "과제 만들기" | 과제 상세. "1조 조장 김민준", "2조 조장 강지우" |

말할 것: "교수는 과제명, 기간, 조마다 조장을 이메일로 지정합니다. 과제·조·조장이 **한 번에** 저장되고, 등록한 뒤에는 고칠 수 없습니다. 조장은 그 조의 첫 조원으로 함께 들어갑니다."

### 장면 2. 조장이 초대 링크를 발급한다 (탭 2, 약 1분)

| 누를 것 | 화면에 나오는 것 |
|---|---|
| student01로 로그인 | 과제 목록에 "웹프로그래밍 조별과제"가 맨 위 |
| 과제 → "1조" | 조원: "김민준 조장 역할 없음"과 역할명 칸, 초대 링크 "아직 발급하지 않았습니다." |
| "발급" | `http://localhost:5173/join/...` 주소 |
| 주소를 세 번 클릭해 선택 → Ctrl+C | |

말할 것: "초대 링크는 **조장만** 발급합니다. 다시 발급하면 이전 링크로는 합류할 수 없습니다."

### 장면 3. 학생이 링크로 합류한다 (탭 3, 탭 4, 약 1분)

| 누를 것 | 화면에 나오는 것 |
|---|---|
| 탭 3 주소창에 링크 붙여넣기 → Enter | 로그인 화면(로그인 전이라서) |
| student02로 로그인 | 로그인 뒤 바로 "조 합류" 화면으로 돌아옴 |
| "합류하기" | 1조 화면. 조원에 "이서연 역할 없음" |
| 탭 4에서 같은 링크로 student03 합류 | 조원에 "박도윤 역할 없음" |

말할 것: "링크를 받은 학생은 로그인하면 바로 합류 화면으로 돌아옵니다. **한 과제에서는 한 조에만** 합류할 수 있습니다."

### 장면 4. 조장이 역할을 배정한다 (탭 2, 약 1분)

| 누를 것 | 화면에 나오는 것 |
|---|---|
| F5(새로 고침) | 조원 3명이 보임 |
| 김민준 칸에 `기획` → "지정" | "김민준 조장" 옆에 파란 꼬리표 "기획" |
| 이서연 칸에 `백엔드` → Enter | "이서연" 옆에 "백엔드" |
| 박도윤 칸에 `프론트엔드` → Enter | "박도윤" 옆에 "프론트엔드" |

말할 것: "역할명은 조장이 정합니다. 조장을 포함해 조원마다 역할 하나이고, **역할이 있어야 산출물을 올릴 수 있습니다.** 지정한 시각은 서버가 기록합니다."

### 장면 5. 조원이 산출물을 올린다 (탭 3, 탭 4, 약 1분 30초)

| 누를 것 | 화면에 나오는 것 |
|---|---|
| 탭 3에서 F5 → "산출물 보기·올리기" | "산출물 올리기" 상자. "올리는 산출물의 역할: 백엔드" |
| 파일 선택 `ERD 초안 v1.txt` → "올리기" | 꼬리표 "백엔드 1번째", `ERD 초안 v1.txt`, "이서연 · 시각" |
| 파일 선택 `ERD 초안 v2.txt` → "올리기" | "백엔드 2번째"가 맨 위에 추가. 1번째는 그대로 남음 |
| 탭 4에서 F5 → "산출물 보기·올리기" → `화면 설계서.txt` 올리기 | "프론트엔드 1번째" `화면 설계서.txt` · 박도윤 |

말할 것: "고친 파일도 **덮어쓰지 않고 새로** 올립니다. 순번은 역할마다 업로드 순서대로 붙고, 업로드 시각은 사용자가 아니라 **서버가 기록**합니다. 파일 본문은 MinIO, 데이터베이스에는 위치·이름·크기만 저장합니다."

### 장면 6. 교수가 열람·다운로드한다 (탭 1, 약 30초)

| 누를 것 | 화면에 나오는 것 |
|---|---|
| 과제 목록 → "웹프로그래밍 조별과제" → "1조" | 조원 3명과 역할. "산출물 보기" 링크(교수에게는 동료평가 링크가 없음) |

말할 것: "교수는 자기가 만든 과제의 모든 조를 봅니다. **조회 수, 다운로드 수는 세지 않습니다.**"

### 장면 7. 조원이 동료평가를 제출한다 (탭 3, 약 1분 30초)

| 누를 것 | 화면에 나오는 것 |
|---|---|
| 맨 위 "← 1조" → "동료평가" | 맨 위 노란 상자에 고정 문구 2줄, 평가 대상 김민준·박도윤 |
| 아무것도 고르지 않고 "입력 내용 확인" | "6개 항목을 모두 고르지 않은 조원이 있습니다: 김민준, 박도윤" |
| 두 사람의 6개 항목을 고름. 김민준 서술 의견에 한 줄 | 고른 점수 줄이 파랗게 표시됨 |
| "입력 내용 확인" | 두 사람의 점수를 항목별로 나란히 보여 주는 표 |
| "제출" | 초록 상자에 "동료평가를 제출했습니다. 제출 시각: ..." |
| F5 | 같은 문구. 다시 입력할 수 없음 |

말할 것: 맨 위 두 줄을 가리키며 "**업로드 횟수는 기여도가 아니고, 점수는 시스템이 계산하지 않습니다.** 판단은 사람이 하고 시스템은 근거만 남깁니다. 자신을 뺀 조원 **전원**을 평가해야 제출되고, 제출한 평가는 고칠 수 없습니다. 평가는 과제를 만든 교수만 봅니다."

## 4. 막혔을 때

| 증상 | 할 것 |
|---|---|
| 로그인하면 "요청을 처리하지 못했습니다" | `docker compose ps`로 4개가 모두 Up인지 봅니다. backend가 없으면 `docker compose up -d` |
| 화면 주소가 `127.0.0.1:5173`이라 로그인이 안 됨 | `localhost:5173`으로 다시 엽니다 |
| http://localhost:8080 이 멈춤(Windows) | 백엔드 주소는 `127.0.0.1:8080`을 씁니다. 화면은 이미 그 주소를 씁니다. 계속되면 Docker Desktop을 다시 시작합니다 |
| 과제 만들기에서 "가입하지 않은 이메일입니다: ..." | 조장 이메일 오타. `student01@example.com` 형식인지 봅니다 |
| 탭이 다른 사람으로 로그인되어 있음 | 그 탭에서 로그아웃하고 다시 로그인합니다 |
| 실시간 진행이 꼬임 | 시작 데이터의 "발자국 시연 과제"로 넘어갑니다. 1조에 조원 5명·역할·산출물 2건(`기획서.txt`, `API 명세.txt`)이 이미 있어서 장면 5~7을 그대로 보일 수 있습니다 |
| 처음부터 다시 | `docker compose restart backend` 후 모든 탭에서 로그아웃 |

## 5. 질문이 나오면

- "점수 평균은 왜 안 보여 주나요?" — 시스템은 점수, 순위, 진척률을 계산하지 않습니다. 기록을 있는 그대로 보여 주고 판단은 교수가 합니다.
- "역할이 바뀌면 순번은요?" — 업로드할 때의 역할명을 산출물에 복사해 저장해서 순번이 끊기지 않습니다. 역할 변경 기능은 2단계입니다.
- "교수는 평가를 어디서 보나요?" — 1단계는 저장까지이고, 교수 열람 화면은 2단계입니다.
- "학교 계정으로 로그인하나요?" — 지금은 시작 계정으로 시연합니다. 학교 구글 계정 로그인은 정해지는 대로 반영합니다.
