# Postman 모음

발자국 데모의 API 43개 중 42개를 요청 146개로 데모 흐름 순서에 맞춰 모음. 요청마다 상태 코드와 응답을 확인하는 test가 붙어 있음
구글 로그인(`POST /auth/google`)은 넣지 않음. 구글이 발급한 ID token을 Postman에서 받을 수 없기 때문. 모음은 시작 계정의 이메일·비밀번호 로그인을 씀

| 파일 | 내용 |
|---|---|
| `footprint-demo.postman_collection.json` | Postman 모음 (Collection v2.1) |
| `sample-upload.txt` | 산출물 업로드 요청이 올리는 시험 파일 |

## 순서

| 폴더 | 내용 |
|---|---|
| 0. 로그인 | 교수, 조장(student01), 조원(student02), 다른 조 학생(student06)으로 로그인해 token을 저장함 |
| 1. 과제 | 교수가 새 과제(조 2개)를 만들고 목록·상세를 봄 |
| 2. 조 운영 | 조장이 초대 코드를 발급하고, 조원이 합류 전 미리보기로 과제 제목, 조 이름, 조장 이름을 본 뒤(교수 403, 같은 과제의 다른 조 409) 합류해 조 정보의 과제 기간을 받고, 조장이 역할을 지정함. 교수가 조장을 바꿔 권한이 옮겨 가는 것을 본 뒤 되돌림 |
| 3. 산출물과 역할 변경, 완료확인 | 조원이 파일을 올리고, 교수가 목록을 보고 내려받음. 올린 조원을 뺀 조원이 완료확인하고 교수가 이력을 봄. 본인이 취소해도 이력에 남고 다시 확인하면 새 기록임. 조장이 역할을 바꾸면 이력이 남고, 올린 산출물의 역할명은 그대로임. 올린 조원이 삭제해도 목록에 남고 다운로드는 404임 |
| 4. 기여 항목과 완료확인 | 조장이 등록하고, 담당 조원이 한 번만 완료 보고하고, 조원과 교수가 목록을 봄. 다시 보고하면 409임. 조장이 보고 전 항목을 취소해도 목록에 남음. 담당 조원을 뺀 조원이 보고된 항목을 완료확인함 |
| 5. 평가 시작과 동료평가 | 기록 단계의 제출은 400임. 교수가 평가를 시작하면 업로드, 삭제, 기여 항목 등록·보고·취소, 완료확인과 취소, 역할 변경, 조장 교체가 400이 되고, 조원이 일부만 임시 저장하고 이어서 불러온 뒤 조장을 평가해 제출함. 임시 저장은 교수에게 403이고 제출하면 비워짐. 다시 내면 409임. 근거 패널은 기록 단계에 조원 400, 교수 200이고, 평가 단계에 조원이 기록을 종류별로 받음. 다른 조 학생 403, 없는 조원 404임. 전체 기록은 두 단계 모두 보이고, 평가 시작 줄이 맨 위에 생기며 평가 제출과 임시 저장은 없음. 역할 변경 줄은 3번 폴더에서 확인함. 평가 결과와 CSV는 교수만 받고, 기록 단계에는 미제출과 빈 목록이며, 제출 후 CSV에 합계, 평균, 순위 열이 없음 |
| 6. 오류 예시 | 401, 403, 404, 400 응답 모양. 400의 `message`에 틀린 칸이 담김(빠진 칸 전부, 숫자 칸에 글자, 주소의 번호가 글자). body가 `code`, `message` 두 칸뿐임 |
| 7. 알림 | 조원이 담당 지정과 평가 시작 알림을, 조장이 완료 보고 알림을 받음. 알림에는 점수, 의견, 건수 칸이 없음. 다른 회원의 알림을 읽음 표시하면 403이고, 다시 읽음 표시해도 처음 시각이 그대로임 |
| 8. 개인정보 고지 동의 | 동의 전 시작 계정(student10)이 동의하면 서버 시각이 저장되고, body에 보낸 시각은 무시됨. 다시 동의해도 처음 시각이 그대로임. token이 없으면 401임. 다시 실행해도 통과함(이미 동의한 상태라 처음 시각이 돌아옴) |

앞 요청이 저장한 값(token, `assignmentId`, `teamId`, `inviteCode` 등)을 뒤 요청이 씀. 그래서 **폴더 0부터 차례로** 실행함
실행할 때마다 새 과제를 만들므로 서버를 다시 켜지 않아도 몇 번이든 다시 실행할 수 있음

## Postman에서 쓰기

1. Postman에서 Import → `footprint-demo.postman_collection.json`을 고름
2. 서버를 켬. 한 번에 실행(`docker compose up -d --build`)이든 개발용 `bootRun`이든 같음
3. 모음 이름 옆 `...` → Run collection → Run을 누르면 처음부터 끝까지 실행함. 요청을 하나씩 보낼 때도 위에서부터 Send 함

알아 둘 것:

- 변수는 모음에 저장됨(모음을 누르고 Variables 탭). 백엔드 주소 `baseUrl`의 기본값은 `http://127.0.0.1:8080`임. Windows에서 `localhost`가 IPv6로 연결되어 멈추는 일이 있어서 `127.0.0.1`을 씀(`docs/worklog.md`의 "한 번에 실행")
- token은 요청마다 Authorization 탭의 Bearer Token에 `{{professorToken}}`처럼 들어 있음. 로그인 요청의 Scripts(Post-response) 탭이 받은 token을 저장함
- 산출물 업로드 요청은 Body 탭의 `file` 칸에 `sample-upload.txt`가 지정되어 있음. Postman이 파일을 찾지 못한다고 표시하면 그 칸에서 이 폴더의 `sample-upload.txt`(또는 아무 파일)를 다시 고름
- 다운로드 요청은 Send 옆 화살표의 "Send and Download"로 파일을 저장할 수 있음

## 가짜 API에 실행하기

`frontend`에서 `npm run mock`을 켠 뒤, 모음의 Variables 탭에서 `baseUrl`을 `http://localhost:3001`로 바꿔 실행함. 같은 test가 모두 통과해야 함(가짜 API의 응답 모양이 실제와 같다는 확인임)
가짜 API는 `frontend/db.json`을 바꿈. 처음 상태로 되돌리려면 `git restore frontend/db.json`을 실행함
업로드 요청이 올린 시험 파일은 `frontend/mock/files/`에 남음. git이 무시하는 파일이지만, 정리하려면 `seed-`로 시작하는 파일을 뺀 나머지를 지움

## 명령줄에서 실행하기 (선택)

Postman 없이 Newman(Postman 모음을 실행하는 명령줄 도구)으로 실행할 수 있음. 저장소 맨 위 폴더에서 실행함. 처음 한 번은 Newman을 내려받음

```powershell
npx newman@6.2.1 run docs/postman/footprint-demo.postman_collection.json --working-dir docs/postman
```

가짜 API에 실행하려면 끝에 `--env-var baseUrl=http://localhost:3001`을 붙임
