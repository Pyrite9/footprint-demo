disable-model-invocation: true

규칙: 생성한 코드는 그날 안에 읽는다. 설명하지 못하는 줄은 다음 생성 전에 고치거나 지운다.

1. `docs/worklog.md`의 오늘 항목과 `git status`, `git diff --stat`으로 오늘 만든·고친 파일 목록을 보여 준다.
2. `$ARGUMENTS`가 있으면 그 파일, 없으면 목록에서 흐름의 핵심인 파일 하나를 고른다(Controller·Service·api 함수 중 로직이 있는 것).
3. 관리자에게 "주석을 보지 말고 이 파일이 요청을 받아 응답할 때까지 무슨 일이 일어나는지 설명해 줘"라고 요청한다. **답을 먼저 말하지 않는다.**
4. 관리자의 설명을 듣고 빠지거나 틀린 부분을 짚는다. 정답을 바로 주지 말고 질문 하나로 다시 생각하게 한다. 예: "이 메서드에 @Transactional이 없으면 어떻게 될까?"
5. 두 번 짚어도 막히는 줄은 비유나 짧은 예시로 설명한다.
6. 끝나면 결과를 `docs/worklog.md`의 오늘 항목에 적는다: 점검한 파일, 설명 못 한 줄, 처리(고침/지움/이해함).
7. 설명 못 한 줄이 남았으면 "다음 생성 전에 처리할 것"으로 표시하고, 다음 /next-step 때 먼저 꺼낸다.
